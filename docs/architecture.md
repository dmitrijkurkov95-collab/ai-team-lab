# Канбан-доска — архитектура спринта 1

Веб-приложение для управления задачами в стиле канбана: колонки статусов, карточки, drag&drop, комментарии.

## Решения

- **Монорепо**: `server/` — бэкенд, `web/` — фронтенд, `tests/` — тесты QA по API
- **Контракт API** — единственная догма: [api-contract.md](api-contract.md). Пока контракт соблюдён, реализация полностью на совести исполнителя (язык, фреймворк, структура — свободно)
- **Стек**: рекомендую FastAPI + SQLite для сервера и vanilla JS или лёгкий фреймворк для клиента, но это рекомендация, не приказ. Аргументируешь альтернативу в PR — принимается
- **Фаза 1 без**: авторизации, websocket'ов, многопользовательности. Всё это — кандидаты в спринт 2

## Зоны

| Зона | Кто | Что внутри |
|---|---|---|
| `server/` | Agent-1 | REST API, персистентность, запуск одной командой |
| `web/` | Agent-2 | доска, карточки, drag&drop, адаптер к API |
| `tests/` | Agent-3 | автотесты по контракту, edge cases, ревью коллег |

## Точка интеграции

Когда оба PR (бэк, фронт) влиты — лид поднимает всё вместе и прогоняет тест-сьют Agent-3. Расхождения с контрактом = баг соответствующей зоны.
