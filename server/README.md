# server — REST API канбан-доски

Бэкенд спринта 1: карточки, статусы, комментарии. Реализует [docs/api-contract.md](../docs/api-contract.md).

**Стек:** FastAPI + SQLite (stdlib `sqlite3`). Без внешних сервисов — база это файл `server/kanban.db`.

## Запуск

```bash
cd server
pip install -r requirements.txt
python run.py
```

Сервер поднимется на `http://localhost:8000`, API — под префиксом `/api/v1`.
При первом старте пустая база заполняется 6 карточками в разных колонках, чтобы доска не была пустой.

Интерактивная документация (Swagger): <http://localhost:8000/docs>

### Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `KANBAN_PORT` | `8000` | порт |
| `KANBAN_HOST` | `0.0.0.0` | интерфейс |
| `KANBAN_DB` | `server/kanban.db` | путь к файлу базы |
| `KANBAN_RELOAD` | — | `1` включает автоперезагрузку при правках |

Начать с чистой доски: остановить сервер, удалить `kanban.db`, запустить снова.

## Тесты

```bash
cd server
python -m pytest tests/ -q     # 37 тестов, ~1 секунда
```

Тесты гоняются на временной БД (`tmp_path`) и не трогают рабочую `kanban.db`; поднимать сервер для них не нужно.

## Эндпоинты

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/v1/cards` | `200` массив по возрастанию `id`; фильтры `?status=`, `?priority=`, `?limit=` + заголовок `X-Total-Count` |
| POST | `/api/v1/cards` | `201` созданная карточка |
| GET | `/api/v1/cards/{id}` | `200` / `404` |
| PATCH | `/api/v1/cards/{id}` | `200` обновлённая / `404` |
| DELETE | `/api/v1/cards/{id}` | `204` / `404` |
| GET | `/api/v1/cards/{id}/comments` | `200` массив по времени создания / `404` |
| POST | `/api/v1/cards/{id}/comments` | `201` комментарий / `404` |
| GET | `/api/v1/health` | `200` `{"status":"ok","cards":N}` — служебный, вне контракта |

Ошибки: `404 {"detail": "..."}` для отсутствующего, `422` для невалидного тела — как в контракте.

Быстрая проверка руками:

```bash
curl localhost:8000/api/v1/cards
curl -X POST localhost:8000/api/v1/cards -H 'Content-Type: application/json' \
     -d '{"title":"Новая карточка","priority":"high"}'
curl -X PATCH localhost:8000/api/v1/cards/1 -H 'Content-Type: application/json' \
     -d '{"status":"in_progress"}'
```

## Структура

```
server/
├── app/
│   ├── main.py       # HTTP-слой: роутеры, коды ответов, CORS
│   ├── schemas.py    # Pydantic-модели и валидация из контракта
│   └── storage.py    # SQLite: единственное место с SQL + seed
├── tests/test_api.py # 37 тестов на свои сценарии
├── run.py            # точка входа
└── requirements.txt
```

Слой хранения отделён от роутеров: заменить SQLite на другую БД можно, не трогая HTTP-часть.

## Решения по реализации

- **SQLite вместо PostgreSQL** — требование «без внешних сервисов»; один файл, `ON DELETE CASCADE` для комментариев.
- **Соединение открывается на каждую операцию**, а не одно на процесс. FastAPI выполняет синхронные обработчики в пуле потоков: общее `sqlite3.Connection` (даже с `check_same_thread=False`) под параллельной нагрузкой затиралось и давало `InterfaceError` → `500` (issue #21). Открытие соединения к локальному файлу стоит десятки микросекунд — цена несопоставима с классом багов, который это снимает. Включены `journal_mode=WAL` и `busy_timeout=5s` против `database is locked` при параллельной записи.
- **`KANBAN_DB=":memory:"` не поддерживается** и падает с явным сообщением: каждое соединение получило бы собственную пустую БД. Для тестов — файл во временной папке.
- **`title` обрезается по краям** (`strip`), строка из одних пробелов = `422`. Контракт требует «непустую строку», а карточка с невидимым заголовком — мусор на доске.
- **CORS `*`** — фронт Agent-2 работает с другого порта. В спринте 1 нет авторизации, так что это безопасно; при появлении логина список origin'ов нужно сузить.
- **`POST /cards` принимает `status`** — в контракте у POST его нет, но так фронт может создать карточку сразу в нужной колонке. Поле опционально, default `backlog`, поведение контракта не нарушается.
- **`PATCH` пустым телом** возвращает `200` и карточку без изменений — это не ошибка, а no-op.
- **`GET /cards?status=невалидный`** → `422` (а не пустой список): молча отдавать пустую доску на опечатке хуже, чем сказать о проблеме. То же для `?priority=`.
- **У `?limit=` нет значения по умолчанию** — без параметра отдаются все карточки. Дефолтный лимит незаметно обрезал бы доску (проверял: при 66 карточках интерфейс показывал 50 и был уверен, что это всё). Потолок `200` действует только на явный `?limit=`, превышение → `422`.
- **Заголовок `X-Total-Count`** в ответе `GET /cards` — сколько карточек под фильтром без учёта `limit`. Позволяет клиенту увидеть урезание.
- **`/health`** — сверх контракта, для интеграции и CI.
