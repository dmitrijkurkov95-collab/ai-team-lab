# tests_e2e/ — сквозные тесты полного стенда (задача #16)

Проверяют **связку**, а не её части: `server/run.py` + `web/serve.py` поднимаются
как подпроцессы, и сценарий проходит тем же маршрутом, которым ходит браузер —
одним origin через прокси.

## Запуск

```bash
python -m pytest tests_e2e -q
```

Серверы поднимать не нужно — фикстура `stack` делает это сама и сама гасит.
Порты выбираются свободными программно: зашитые `8000`/`5173` однажды упадут
на раннере, где идёт вторая джоба.

## Что покрыто

| Проверка | Зачем |
|---|---|
| страница отдаётся, ключевые элементы на месте | иначе «страница есть, а доски нет» |
| `/api/v1` жив через прокси | прокси — единственная точка входа для браузера |
| статика и API с одного origin | в этом и смысл прокси: без него нужны два порта и CORS |
| создать → переместить → комментарий → удалить | пользовательский сценарий целиком |
| тело ответа через прокси == тело напрямую | прокси ничего не искажает |
| `404`/`422` через прокси == напрямую | прокси переписывает заголовки и сам ставит `Content-Length` — место, где ошибка легко теряет тело |
| `204` без тела | классическое место, где прокси ломается |

## Почему отдельная джоба CI, а не расширение `qa-contract`

У сьютов **разный контракт на окружение**:

* `qa-contract` — один живой API, джоба сама поднимает сервер и ждёт health-check;
* `qa-e2e` — два процесса в правильном порядке старта, и тесты управляют их
  жизнью сами.

Смешать их значит: (1) красить одну джобу по двум разным причинам и каждый раз
разбираться, что именно упало; (2) тянуть фронтенд в каждый локальный запуск
`pytest tests`; (3) связать два разных способа ожидания готовности.

Цена отдельной джобы — пара секунд на `setup-python`. Оно того стоит.

## Поведение при сломанном стенде

Если процесс умер на старте, фикстура **не досиживает таймаут**, а падает сразу
и печатает вывод обоих процессов:

```
RuntimeError: процесс ['python3', 'serve.py', '--port', '36407'] умер сразу с кодом 2, ...
Логи процессов:
--- python3 serve.py --port 36407 (код 2) ---
python3: can't open file '.../web/serve.py': [Errno 2] No such file or directory
```

Это не косметика, а исправленный баг самой фикстуры: первая версия читала логи
**до** остановки процессов, а `stdout.read()` на живом процессе блокируется до
EOF. При сломанном стенде pytest висел до таймаута вместо внятной ошибки —
поймано прогоном с убранным `web/serve.py`.

## Что нужно от лида: добавить джобу в CI

Готовая джоба лежит в [`ci-job.yml.snippet`](ci-job.yml.snippet) — вставить в
`.github/workflows/pr-checks.yml` на одном уровне с `qa-contract`.

**Сам я это сделать не могу:** рабочий токен не имеет скоупа `workflow`, и push
с правкой в `.github/workflows/` отклоняется:

```
! [remote rejected] (refusing to allow a Personal Access Token to create or
  update workflow `.github/workflows/pr-checks.yml` without `workflow` scope)
```

То есть критерий «e2e живёт в CI» закрыт наполовину: тесты написаны, проверены
локально (11 passed) и готовы к запуску в CI одной командой, но саму джобу
должен добавить тот, у кого есть `workflow`-скоуп. Это ограничение доступа,
а не незавершённая работа.
