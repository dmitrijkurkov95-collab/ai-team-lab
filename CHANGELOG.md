# Changelog

## v1.0 — 27.08.2026

Первый официальный релиз канбан-доски, собранный командой ИИ-агентов
(team-lead-agent, Agent-1, Agent-2, Agent-3) за два дня работы: 30+ влитых PR,
~490 автотестов, непрерывно зелёный main.

### Возможности
- Карточки: создание, правка, удаление, 4 колонки, приоритеты, дедлайны
- Список: фильтры (`status`, `priority`), поиск (`q`), сортировка, пагинация
  (`limit`/`offset`), `X-Total-Count`
- Комментарии к карточкам
- Экспорт/импорт доски в JSON (режимы `replace`/`merge`)
- Живой интерфейс: drag&drop, живой рефреш (polling), офлайн-очередь правок с
  политикой разрешения конфликтов (done/gone/conflict/overwritten/rejected)
- Стенд одной командой: `docker compose up` или `./run.sh` без Docker

### Безопасность
- Деструктивный импорт требует `X-Confirm-Replace` (иначе `428`)
- Потолки импорта: 10 000 карточек / 2 MB (`413`)
- Опциональный токен записи `KANBAN_WRITE_TOKEN` (все мутации — `X-Auth-Token`)
- XSS-экранирование на клиенте; SQL-параметризация на сервере

### Качество
- CI: 7 джоб — серверные, контракт-сьют, нагрузочная, e2e, UI (Playwright),
  синтаксис Python + ES-модулей
- Контракт API зафиксирован в `docs/api-contract.md` (включая арбитраж
- неоднозначных случаев)
- Известное ограничение: повторное использование Docker-volume, принадлежащего
  root, не привилегированным пользователем контейнера даёт отказ БД
  (штатный первый запуск работает; см. #9, доклад Agent-2)

### Процесс (не продукт, но важно)
- Мерж — только лидом; журнал мерджей + автотревога на чужой мерж
- Правила: одно «беру», свежесть ветки, очередь без простоев, честные пост-мортемы
- Инцидент самомерджей разобран публично; контроли развёрнуты
